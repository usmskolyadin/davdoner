# Dav Doner Club — сайт-магазин

Django-проект: каталог блюд, корзина, оформление заказа (доставка/самовывоз) и админ-панель
для самостоятельного управления меню, категориями, баннером и заказами.

## Запуск локально

```bash
python -m venv .venv
. .venv/Scripts/activate        # Windows (PowerShell/Git Bash)
pip install -r requirements.txt

python manage.py migrate
python manage.py seed_demo      # демо-данные: категории, блюда, баннер, настройки доставки
python manage.py runserver
```

Создайте локальный `.env` по образцу `.env.example` и задайте секреты эквайринга.
Файл `.env` исключён из Git. Переменные `T_TOKEN` и `T_CLIENT_ID` пока читаются как
совместимые псевдонимы для `TOCHKA_JWT_TOKEN` и `TOCHKA_CLIENT_ID`. Интеграция использует
Acquiring API v1.0. Онлайн-оплата остаётся выключенной (`TOCHKA_ENABLED=false`) по умолчанию.
До её включения задайте sandbox/production credentials, `TOCHKA_CUSTOMER_CODE` и публичные
HTTPS URL для возврата после оплаты и webhook. Сначала зарегистрируйте и проверьте webhook,
затем проведите тестовый платёж в sandbox; включайте оплату только после этого.

Сайт: http://127.0.0.1:8000/
Админ-панель: http://127.0.0.1:8000/admin/

Команда `seed_demo` создаёт суперпользователя `admin` / `DavDoner2026!` (смените пароль
после первого входа) и демо-покупателя `demo_client` / `DemoClient2026!` с одним заказом
в истории — для проверки личного кабинета.

## Структура проекта

- `pages/` — главная страница, баннер, преимущества, глобальные настройки сайта (бренд, SEO).
- `menu/` — категории, блюда, добавки/соусы; каталог, страница категории, карточка товара, поиск.
- `orders/` — корзина (на сессии), оформление заказа, настройки доставки, заказы в админке.
- `accounts/` — регистрация/вход, личный кабинет с историей заказов.
- `templates/`, `static/` — вёрстка и стили (без сторонних UI-фреймворков, чистый CSS).

## Что сейчас демонстрационное

- Фотографии блюд — примеры (обрезаны из согласованных заказчиком макетов №12 ТЗ),
  для продакшена их нужно заменить на реальные фото кафе через админку (поле «Фотография»
  у блюда/категории/баннера).
- Названия, состав и цены блюд — демо-данные, см. раздел «Открытые вопросы» в чате.
- Подготовлены запросы создания платёжной ссылки и сверки статуса Точка.API, модель попытки
  платежа, безопасный отказ от слепого повтора POST, проверка подписи JWT webhook, сверка суммы
  и экран статуса. Команда `register_tochka_webhook` безопасно проверяет подписку и не заменяет
  существующие настройки; при HTTP 404 регистрация требует явного `--confirm-not-found`.
- `python manage.py reconcile_tochka_payments` сверяет незавершённые попытки оплаты. Запрос денег
  на возврат намеренно не реализован до подтверждения схемы refund API. Фискализация выключена,
  пока заказчик не подтвердит требования онлайн-кассы и налоговые параметры.
